## 1. 测试方法

### 1.1 测试音频

- 20 个送气清声母短词 × 2 语音 = 40 WAV
- TTS 引擎：Windows SAPI（Microsoft Huihui Desktop）
  - v1：语速 0（正常）
  - v2：语速 -2（较慢，因 Microsoft Yaoyao 未安装，以同 voice 不同语速替代）
- 格式：16kHz 16bit 单声道 WAV（SAPI 直出，无重采样）
- 文件名改用 ASCII 别名以规避 Windows 中文路径编码问题

### 1.2 对比组

| 组 | 模型 | 模型目录 |
|---|------|---------|
| (a) | SenseVoice (生产) | `models/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2025-09-09` |
| (b) | FunASR Nano CTC 179MB | `models/sherpa-onnx-sense-voice-funasr-nano-int8-2025-12-17` |
| (c) | FunASR Nano Native 972MB | `models/sherpa-onnx-funasr-nano-int8-2025-12-30` |
| (d) | FunASR Nano Native + hotwords | 同上 + `--hotwords "派,派对,派发,派出所,七,七百,七点,厂,厂家,踢,踢球,开,开放,快,口,气,切,泡,跑,票"` |

### 1.3 评分规则

- **首字正确**：识别文本第一个字 == 目标词第一个字
- **整词正确**：识别文本 == 目标词（忽略标点符号 `。，、！？`）
- 整词正确率不受标点影响（native 模型输出含句号）

## 3. 逐词分析

### 3.1 Hotwords 显著改善的词

| 词 | (a)→(d) | 说明 |
|----|---------|------|
| 口 | CO→口 | 从完全无法识别到正确，hotwords 建模直接提升 |
| 跑 | 炮→跑 | hotwords 精准纠正送气声母 |
| 泡 | (a)炮/(b)泡→跑/套 | 有部分改善但不稳定 |
| 开v2 | 嗨→开 | hotwords 送了正确的首字 |

### 3.2 Hotwords 未能改善的词

| 词 | 所有组表现 | 说明 |
|----|-----------|------|
| 厂 | 唱/岔——全部错误 | hotwords 列表中无"厂"（只有"厂家"），单字"厂"未覆盖 |
| 踢 | T/t/踢/七——仍错误 | 送气音 tʰ 对 LLM decoder 仍困难 |
| 切 | 切→七——反而变差 | native 模型（含 hotwords）把切误判为七 |
| 气 | 气→汽——部分误判 | 气→汽（同声母，韵母误判） |

### 3.3 179MB CTC 的亮点

- **泡**：179MB CTC 完美识别（泡/泡），生产/原生均失败
- **派出所**：179MB CTC 全部正确（派出所/派出所），生产 v1 丢了"派"
- 整体首字正确率 75.0%，高于生产基线 70.0%

### 3.4 Decoder Hallucination（值得关注）

**qidian_v1.wav 在 (d) 组**触发 decoder 崩溃：

> 输出：`七点 managers what Stayers she went to buy their playback B卡取回的扇形画向令 paddle 把眼一睁开放在客厅和屋里等日记日后家庭调查跟踪等，勘验死人一事海鹏被警察抓去审查这么一个案子，尤其这是民法上河南不改Upフレch这一编号，就：1937年普通转换出现考的碎片字串`

- WAV 时长：1.37s → 推理耗时：**3.642s**（RTF 2.66，比正常高 20 倍）
- 根因推测：hotwords 注入后 LLM decoder 在特定音频条件下陷入循环/幻视

## 6. TTS 局限声明

- **合成音 vs 真人**：TTS 合成的送气声母起始比真人清晰，可能无法完全复现 Gavin 真实发音的送气声母弱化（尤其是自然语流中的送气弱化）
- **最终验证**：以 Gavin 实机端测为准
- **Yaoyao 语音缺失**：Microsoft Yaoyao Desktop 在本机未安装，v2 改用 Huihui + 语速 -2 作为替代变体
- **路径编码**：PoC bin 对中文路径的 fopen 支持存在问题，改用 ASCII 别名文件名规避

## 7. 结论与建议

### 7.1 通过判定：✅ **通过**

(d) native + hotwords 首字正确率 80.0%：
- 较 (a) 生产基线 +10.0pp → 达标（≥10pp ✅）
- 较 (c) native 无 hotwords +17.5pp → 达标（≥5pp ✅）

### 7.2 关键数据点

1. **Hotwords 确有增量**：(d) vs (c) +17.5pp 说明 config 层 hotwords 注入显著改善送气短词首字
2. **提升幅度在阈值边缘**：+10pp 恰好达标——若用真人发音而非 TTS 合成音，改善幅度可能更大（TTS 声母更清晰，基线已偏高）
3. **179MB CTC 是零风险选择**：无需 hotwords 即达 75.0%，且模型加载 1.48s、推理 0.028s/词、内存 362MB——如果不需要热词纠偏，这是最安全的升级路径
4. **Native 有 hallucination 风险**：qidian_v1 触发 decoder 崩溃（RTF 2.66，输出 146 字乱码），需生产环境兜底
5. **推理延迟翻倍**：(d) 组 hotwords 场景平均 0.438s/词（vs 生产 0.031s），用户感知延迟显著

### 7.3 建议

| 路线 | 推荐度 | 理由 |
|------|--------|------|
| 179MB CTC 直换 | ⭐⭐⭐ 推荐 | 零风险，首字 75%，速度更快，内存更低 |
| Native + hotwords | ⭐⭐ 可选 | 首字 80%，但有 hallucination 风险 + 14x 推理耗时 |
| 保持现状 | ⭐ 不推荐 | 首字 70.0%，模型代际差距明显 |
