## 一、完整产出源盘点（代码取证）

标点会从 **6 个地方**进入最终文本：

| # | 产出源 | 位置 | 说明 |
| --- | --- | --- | --- |
| ① | ASR native 自带 | `src/transcription/mod.rs:278`（Qwen3）/ `:439`（accuracy native） | 返回 `native_punctuated=true` |
| ② | 本地标点引擎 | `src/punctuation/mod.rs:44`，调用点 `src/main.rs:3574` | sherpa-onnx CT-Transformer |
| ③ | LLM optimize 提示词 | `src/llm/mod.rs:68` `ADD_PUNCT`，装配点 `:401` | 受开关控制（软约束） |
| ④ | LLM translate 提示词 | `src/llm/mod.rs:694` `punct_instruction` + **`:705` 硬编码** | `:705` 不受开关控制 |
| ⑤ | LLM 列表分隔符 | `src/llm/mod.rs:1014` `INLINE_SEPARATOR_RULES` | 要求用 `、` `；` `,` `;` 做枚举分隔，**完全不受开关控制** |

## 三、开关 `config.punctuation.enabled` 的真实控制面

| 产出源 | 开关是否生效 | 缺口原因 |
| --- | --- | --- |
| ① ASR native | ⚠️ 部分 | 仅当 `!llm_handled && !translate_requested` 才剥 |
| ② 本地引擎 | ✅ 完全生效 | 唯一真正受控的一条 |
| ③ LLM optimize | ⚠️ 软约束 | 关闭时只是**不追加**指令，没有任何禁止句；且无后置剥离兜底 |

**结论：6 个产出源，开关只完全控制 1 个。**

## 四、架构缺陷本质

> **标点的「产出」分散在 6 处，「治理」只在 1 处；而那 1 处的判据是「来源判据」而非「意图判据」。**

治理点现在写的是 `!llm_handled && !native_punctuated && !translate_requested` —— 这是在问
**「标点是谁放进去的」**。但开关表达的是**「用户要不要标点」**，是意图，与来源无关。

用来源判据实现意图，后果是**每新增一条产出路径，开关就自动失效一次**，且失效是静默的。
④⑤⑥ 三条正是这样漏掉的。

这是 `[ITN-LOCAL-RULE-OVERREACH-001]` 的镜像形态：
- ITN 那个是**局部规则没约束自己的适用范围**，在更长上下文里越界生效
- 这个是**全局意图没贯彻到所有分支**，新增分支时静默失守

两者同属「规则的作用域没有被显式建模」。

## 五、源头可控性核实（2026-08-08 主控实测 + 官方文档核实）

> **Gavin 指示**：「不应该把所有剥离动作放在统一后处理，应该在开关关闭时，
> 无论在线 ASR 还是本地模型，传入的时候就明确要求不要带标点；后端 LLM 也是。」
>
> 原则成立且优于「产出后再剥」——剥离是破坏性的，会留下语义空洞。
> 但需先核实各引擎**物理上是否具备源头控制能力**，结果如下。

| # | 产出源 | 源头能否关 | 依据 |
| --- | --- | --- | --- |
| ① | Qwen3 在线 ASR | ❌ **不能** | 阿里云 `session.update` 仅支持 `input_audio_format` / `sample_rate` / `input_audio_transcription.language` / `turn_detection`，**无任何标点参数**（官方 client-events 文档核实） |
| ①' | 本地 Accuracy native | ❌ **不能** | sherpa-onnx 模型内建标点，`src/transcription/mod.rs:439` 直接返回带标点文本，无 API 开关 |
| ①'' | 本地 Performance (CTC) | ✅ 天然无标点 | 本就不产标点 |
| ② | 本地标点引擎 | ✅ **能** | 不调用即可，现有代码已实现 |
| ③ | LLM optimize | ⚠️ 能要求，软约束 | 现状只是**不追加**指令，**无任何禁止句** —— 缺陷 |
| ④ | LLM translate | ⚠️ 同上 + `:705` 硬编码 | |
| ⑤ | LLM 列表分隔符 | ⚠️ 提示词可条件化 | |
| ⑥ | 本地 NLLB 翻译 | ❌ **不能** | seq2seq 模型，译文继承输入标点，无参数可传 |

**结论：①①'⑥ 三条物理上无法在源头关闭，兜底层不可省。**

## 六、最终架构：源头控制为主，后处理补位

### L1 源头控制（主路径）

开关关闭时，**能在源头关的一律在源头关**：

| 源 | 动作 |
| --- | --- |
| ② 本地标点引擎 | 不调用（现有逻辑已实现） |
| ③ LLM optimize | 提示词从「不追加 ADD_PUNCT」升级为**明确禁止句**（现状是空的，LLM 收不到任何禁止信号） |
| ④ LLM translate | 同上；且 `src/llm/mod.rs:705` 硬编码的 `Correct ... punctuation ...` 必须条件化 |
| ⑤ LLM 列表分隔符 | `INLINE_SEPARATOR_RULES` 按开关条件化装配 |

理由：让 LLM 一开始就不产出，比产出后再剥质量高得多——剥离会让列表结构塌陷、
语义空洞，而源头不产出得到的是自然的无标点文本。

### L2 后处理补位（不是主机制）

位置：`src/main.rs` 标点决策块结束后、`cancel_signal` 检查前（现 `:3611` 与 `:3612` 之间）。

**只负责两件 L1 够不着的事**：

| 职责 | 原因 |
| --- | --- |
| (a) 开关关闭时剥离 ①①'⑥ 的标点 | 这三条源头物理不可控，不兜底则开关对它们零效果 |
| (b) 开关开启时，字/词数 ≤5 剥末尾标点 | **Gavin 2026-08-08 明确指示放后处理点**。本质使然：需先拿到最终文本才知道字数，ASR 出结果前无法预判；让 LLM 自己数字数是不可靠的软约束 |

```
if !enabled              → 剥全文标点（标点位置换空格）
else if count_units(text) <= SHORT_TEXT_UNIT_THRESHOLD  → 剥末尾标点（直接删，不留空格）
else                     → 原样返回
```

**契约要点**：

1. **不含任何来源判据** —— 不写 `llm_handled` / `native_punctuated` / `translate_requested`。
   L1 做得好时 L2 自然是 no-op（文本本来就没标点），不需要靠来源判断跳过。
   这保证将来新增第 7 个产出源也自动受控。
2. **确定性** —— ③④⑤ 的禁止句是软约束（LLM 是概率模型），L2 提供确定性保证。
3. **幂等** —— 重复应用结果不变。

### Q2 追加要求的落地口径（主控判定，Gavin 未细说的部分）

Gavin 原话：「不能简单地只是把原来的标点符号去掉，原来有标点符号的地方，那应该要留空格。」

| 场景 | 口径 | 理由 |
| --- | --- | --- |
| 全文剥离（`enabled=false`） | 标点 → **替换为空格**，连续空格合一，首尾 trim | 直接执行 Gavin 要求 |
| 短句末尾剥离（`enabled=true` 且 ≤5） | 末尾标点**直接删除并 trim_end**，不留空格 | 末尾留空格是纯粹的垃圾字符，注入后光标前多一个空格，体验更差。Gavin 说的「留空格」针对的是句中标点造成的词间粘连 |
| 小数点 / URL 等受保护字符 | 维持现有保护逻辑不变 | `strip_punctuation:490` 已有数字间小数点保护 |

### 🔴 已上线行为变更警示

`transcription::strip_punctuation` 生产调用方只有 `src/main.rs:3600` 一处，改动面可控。
但**现有 5 条单测断言会翻**（`src/transcription/mod.rs:1052-1121`），例如：

| 用例 | 现状 | 新规则 |
| --- | --- | --- |
| `你好，  世界！` | `你好 世界` | 待实测确认 |
| 引号用例 `:1115` | `你好他说` | 会变（引号位置补空格） |

**要求实施方先跑现状、记录实际输出，再改断言** —— 不得凭推断改测试。
