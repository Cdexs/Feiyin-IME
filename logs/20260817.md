## 2026-08-17 — OVERLAY-043-B 完成：抽两个纯函数补真护栏（coder-2）

**性质**：阶段一补强，纯可测性重构，**行为零变更**。

### 改动摘要

| 函数 | 原位置 | 用途 | 契约 |
| --- | --- | --- | --- |
| `interpolate_step(delta: i32) -> i32` | `main.rs:1203-1206` 内联 | 尺寸插值每帧步长 | `delta==0 -> 0`；至少 1px；至多 25% 剩余距离；不超过剩余距离；正负对称 |
| `should_ignore_streaming_text(stopped, editing) -> bool` | `main.rs:2993-2995` 内联 | 晚到流式包是否忽略 | 真值表四格：`false/false`=不忽略、`false/true`=不忽略、`true/false`=忽略、`true/true`=不忽略 |

### 等价性自证

- `interpolate_step`：原内联为 `(dx.abs() as f32 * 0.25).max(1.0).min(dx.abs() as f32) as i32 * dx.signum()`。抽出后函数对该表达式逐字复现，仅把 `dx` 换成参数 `delta`。正负对称性由最后乘 `delta.signum()` 保证；`delta==0` 显式返回 0（避免 `0.signum()==0` 与 `0.0.max(1.0)` 歧义）。
- `should_ignore_streaming_text`：原内联为 `STREAMING_STOPPED && !OVERLAY_EDITING`。抽出后函数直接计算 `stopped && !editing`，与原布尔表达式逐位等价。

### 为什么不做行为变更

- 这不是优化机会，而是给刚塌过的 `interpolate_step` 负数方向缺陷补测试锚点。
- `should_ignore_streaming_text` 把竞态门闩从 `AtomicBool` 读取逻辑中剥离，使四格真值表可被阶段三 tester-1 写纯函数测试。

## 2026-08-17 — OVERLAY-046：修复录音 overlay 窗口未被定位/定尺寸（P0，BUILD-018 端测回归）

**性质**：缺陷修复，仅改 `src/main.rs`，**Windows-only `#[cfg(target_os = "windows")]` 区域**。

### 根因

Gavin 端测 BUILD-018 报「按下热键录音窗口完全不出现」。主控 `git show 56bfa37:src/main.rs`（OVERLAY-043 之前）对照 HEAD `664b7bd` 取证：Show 分支原有无条件 `SetWindowPos` + `InvalidateRect`，OVERLAY-043 重构后仅剩 `SetLayeredWindowAttributes` + `ShowWindow(hwnd, SW_SHOWNA)` + 条件 `SetTimer`。

非流式 `OverlayStatus` 在 Show 分支 `:991-993` 执行 `state.target_size = computed_size; state.current_size = computed_size;` → 二者恒等 → `:1198` 插值条件 `current_size != target_size` 永为 false → `size_interpolation_done` 永不置位 → `:1221` 的 `SetWindowPos` 永不执行。窗口从未被定位/定尺寸，`SW_SHOWNA` 后仍在 `(0,0,0,0)` 或旧位置，肉眼不可见。

### 修法

在 `src/main.rs:997` Show 分支的 unsafe 块内、`ShowWindow` **之前**恢复无条件定位；`ShowWindow` 之后补 `InvalidateRect(hwnd, None, false)`（保持 043 的 `bErase=false` 红线）。

```rust
let _ = SetWindowPos(
    hwnd,
    None,
    request.pos[0],
    request.pos[1],
    computed_size[0],
    computed_size[1],
    SWP_NOACTIVATE | SWP_NOZORDER,
);
let _ = ShowWindow(hwnd, SW_SHOWNA);
let _ = InvalidateRect(hwnd, None, false);
```

### 为什么不会破坏 043 的流式插值动画

以一次流式 `RecordingWithText` Show 为例：

1. `computed_size` 来自 `:930-959`：若距上次 resize ≥100ms，调用 `adjust_overlay_pos_size_for_text` 得到 `size`，写入 `state.target_size = size` 与 `state.pending_size = Some(size)`，并把窗口居中后的 `[x, y]` 写回 `request.pos`；若 <100ms，把 `pending_size` 赋给 `request.size`。
2. 对 `RecordingWithText`，`:991-993` 的恒等赋值被跳过，因此 `current_size` 保留上一帧值（首次可能为默认 240×36），`target_size` 为最新目标尺寸。
3. 本次新增的无条件 `SetWindowPos` 使用 `computed_size`——它正是 `pending_size` 或最新 `target_size` 的同源值——把窗口直接放到正确位置与目标尺寸。
4. 下一帧 16ms timer 检测到 `current_size != target_size`，`interpolate_step` 仍会按 25% 步长平滑推进 `current_size → target_size`；后续流式文字继续更新时，`target_size` 仍由 `:930-959` 控制，`pending_size` 防抖逻辑不变。Show 时的这一次性定位只是「从正确起点开始」，不会打断、覆盖或重置插值状态机。
