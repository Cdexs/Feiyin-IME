## 2026-05-01 - TRANS-CT2-EMPTY-002 direct CT2 FFI fix

- Investigated `C:\Users\Aaron-GMK\.cargo\registry\src\index.crates.io-1949cf8c6b5b557f\ctranslate2-2.1.1\src\translator.rs` before editing product code.
- Confirmed the active empty-result bug is in the wrapper layer, not in SentencePiece tokenization.
- Root cause on the runtime path was twofold:
  - `TranslationOptions::default().max_batch_size = 0` was preserved, while `ctranslate2-sys/cpp/translator_wrapper.cpp` rejects `max_batch_size == 0` and returns `nullptr`.
  - `prepare_string_pts()` returned pointers into a temporary `Vec<Vec<*const c_char>>`, so the subsequent C call received dangling `const char***` pointers.
- Product fix in `src/translation/mod.rs`:
  - replaced runtime use of `ctranslate2::Translator::translate_batch(...)`
  - added a local `Ct2Translator` built directly on `ctranslate2_sys`
  - kept the current beam/penalty/no-repeat/decode-length settings unchanged
  - explicitly documented the lifetime guarantees around `CString`, token pointers, and source pointers in the unsafe block
  - limited the new FFI path to the current product requirement: single source sentence per call
- Verification passed:
  - `cargo fmt --all`
  - `cargo check --manifest-path Cargo.toml`
