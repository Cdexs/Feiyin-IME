## 2026-09-03 — ASR-074 根因定位：音频上行背压 + 松手丢弃积压（Gavin 受控复现日志实证）

**数据源**：`target/release/debug.log`（mtime 09-03 17:28），Gavin 真人真麦克风受控复现一次，
非 TTS 放音，**是本议题第一份未被污染的数据**。

### 硬数据

| 事实 | 数字 | 日志出处 |
| --- | --- | --- |
| 热键按住 | 12.55s | `record_streaming() completed after +12554.6ms` |
| 实际采集音频 | 9.03s（433440 samples @48k） | `Streaming recording complete` |
| **凭空消失** | **3.52s** | 相减 |
| 发送 9.0s 音频耗时 | 13.86s（慢于实时 4.9s） | `finish-task sent after 13.9s streaming` |
| 录音结束 → finish-task | 4.05s | 08.433 → 12.483 |

### 因果链（推定，第 2 步待 coder-1 实测坐实）

1. 流式主循环每轮只 `try_recv` 一个 chunk（`qwen_inference.rs:1284` 起），一 chunk = 10ms 音频，
   要跟上实时须 ≥100 Hz
2. 🔴 **推定**：`set_socket_timeouts(1ms)`（`:1276-1282`）在 Windows 上受 `SO_RCVTIMEO`
   计时器分辨率（~15.6ms）限制，实际循环约 64 Hz → 每秒净积压 36 chunk。
   **与 tester-1 REPRO-070「≥4s 音频才丢、3.3s 短句不丢」精确吻合**
3. 撑破两级缓冲（`main.rs:4263` bounded 256、`audio/mod.rs:405` bounded 256）后，
   生产端 `audio/mod.rs:432`/`:464` 的 `let _ = tx_audio.try_send(...)` **静默丢帧，零日志**
   → **录音中途丢音频 = ASR-067**
4. 松手时 `audio/mod.rs:290-293` `stop_signal` **立即 break，不 drain 队列**，积压全部丢弃
   → **尾部丢字 = ASR-070**
5. 松手后 `chunk_rx` 残留积压仍需逐个发完才 Disconnected 触发 finish-task
   → **4.05s「finalize 拖尾」是客户端自己拖的，不是服务端慢**

**一条机制同时解释 067 与 070，服务端完全无辜。** tester-1 REPRO-073 报的
「服务端 word 流停在结尾词之前、从未到达客户端」观察正确，但归因为「服务端未返回」方向错了 ——
那段音频我们压根没发出去。

🔴 **主控更正**：`958cadb`（`final_text()` 返回 confirmed+current）是真缺陷、修法正确、予以保留，
但救不了本症状。主控 08-30 曾报「尾部丢字已修复」，结论下早了。

**Gavin 独立提出同一判断**（09-03）：「系统依据何时松开热键作为录入结束的标志，
而不是所有语音上传到 ASR 服务器并返回作为结束的标志」—— 与代码 `audio/mod.rs:290-293` 完全一致。

### 顺带查实的三个独立缺陷（已并入 coder-1 任务书）

## 2026-09-03 — coder-2 — OVERLAY-075 跨 session 流式文本渗漏隔离（src/main.rs +44/-5）

**根因**（2026-08-30 068 覆盖面核查的后续，主控裁定本批必修）：`STREAMING_STOPPED` 布尔门闩
表达不了「这包属于哪一次会话」。session A finalize 拖尾期间开 session B → 门闩被
RecordingStarted 重置为 false → A 迟到 StreamingText 畅通 → 与 B 的 Recording(240) 交替
Show（宽窄拉锯），且 A 旧文字渲染进 B 窗口（内容错误，优先级上调）。

**修法**：会话代际（generation）身份判断取代时序判断。
- `StreamingText(u64, String, Vec<WordTiming>)` 加代际首字段
- `static STREAMING_GENERATION: AtomicU64`（紧邻 STREAMING_STOPPED）
- worker Start 分支 `fetch_add(1)` 声明代际 → ASR 闭包捕获 → 每包加戳 →
  消费侧 `gen != current` 丢弃（log::debug + continue）
- `STREAMING_STOPPED` 语义未动（OVERLAY-043 红线）：代际管跨 session 身份，043 管本 session
  松手后尾包，两闸正交相与
- 实施自查纠错：第一版闸门放在 WORDBOOK-053-B 镜像之后，旧 session 文字会污染词库学习镜像，
  已移到镜像之前（闸门必须先于一切消费）
