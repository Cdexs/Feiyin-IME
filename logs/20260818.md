
`.max()` 取大者，`top+10` 这一项**恒大于居中值**（36px 窗口内，居中值最大也才 `top+8`），

### FUN-UI-004 · tester-1 阶段三查出的真实 UI 缺陷（主控直接修复）

**现象**：切换 ASR 模型时 `asr_online_model` 的同步**静默失效**。

**根因**：`handleAudioChange` 每次都从**本次渲染捕获的** `config` 展开：

```tsx
const handleAudioChange = (field, value) =>
  updateConfig({ ...config, audio: { ...config.audio, [field]: value } });
```

连续调用两次时，第二次用的仍是**同一份陈旧 `config`** →
第一次写进去的 `asr_online_model` 被第二次整体覆盖掉，只有 `asr_model` 活下来。

**修法**（主控直接改，未返工）：改为**单次 `updateConfig` 一起写两个字段**。

🟢 **这里有一个正面结论值得记**：即便同步丢了，运行时**并没有连错模型** ——
`resolve_online_model_id` 的族前缀守卫捕获了「变体是 fun-asr、配置串还是 qwen」
这一冲突，warn 后回落到族默认串。**纵深防御真的兜住了一次**：
UI 层漏了，配置层挡住了。这也反证主控当初坚持加守卫（而非纯靠 UI 同步）是对的。

**为什么阶段三才发现**：这是 React 闭包捕获陈旧 state 的经典坑，
