## 2026-09-10 — VERIFY-206 多轮 A/B 定案：**根因是 config.toml 里的陈旧用户基座**

### 🔴 先修正方法论错误

VERIFY-205 的四组结论**全部建立在单次采样上**，而 `temperature=0.3` 有随机性。
实测同一配置（旧基座 + 无 F3-CORE）两次跑出相反结果（0 bullets / 3 bullets）
⇒ **单次 A/B 不足以定论**。VERIFY-205 的 H1/H2/H3 证伪与 H4 成立**均不可靠，予以作废**，
以本条多轮采样结论为准。

### 多轮采样（N=5 × 2 轮 = 每组 10 次，同用例同模型同场景）

| 组 | 第 1 轮 | 第 2 轮 | 合计 | 各轮 bullets |
| --- | --- | --- | --- | --- |
| **A 生产 config.toml 旧基座（2,384 chars）** | 1/5 | 1/5 | **2/10（20%）** | [0,3,0,0,0] / [0,3,0,0,0] |
| **B 代码新 default（1,184 chars）** | 4/5 | 5/5 | **9/10（90%）** | [3,3,3,0,3] / [3,3,3,3,3] |

**唯一变量 = 用户基座**（prompt 架构、F3 块 13,789 chars、模型、场景、输入全同）。

### 根因

`Publish/config.toml` 的 `llm.system_prompt` 存的是**旧版本默认值**（7 条规则，2,384 chars），
当前代码 default 只有 3 条（1,184 chars）。旧基座与现行架构多处冲突，致命的是：

> **5. List Formatting: Convert enumeration (第一点/第二点, firstly/secondly) to Markdown lists.**

**它把列表化窄化成只认「第一点/firstly」这类有序标记**，而 Gavin 用的是「比如/再比如/还有比如」
无序标记 —— 不在其白名单内。用户基座在 **L2**，`USER_PREFS_HEADER` 明写它
`may refine L2/L3 behaviour` ⇒ **L2 合法压过 L3 的 F3 语义判断**。

配合第 1 条 `Transcription Error Correction ONLY / DO NOT change words the user clearly intended`
（语义上禁止结构重排），形成双重压制。

**旧基座其余冲突项**（一并记录，修复时同时消除）：
- 第 2 条 `MANDATORY Punctuation: You MUST add punctuation` ⇔ 与 `ADD_PUNCT`/`NO_PUNCT` 开关冲突（关标点时自相矛盾）
- 第 7 条 suggestions JSON 格式 `{"suggestions":[{"raw":..,"corrected":..}]}` ⇔ 代码 `SUGGESTION_INSTRUCTION` 用 `{"suggestions":["correct_word"]}`，**格式不符可致词库建议解析失败**
- 末句 `Return ONLY the processed text. No explanations.` ⇔ 与 L1 的 `<corrected>` 标签契约冲突

### 被本条推翻的三个结论

| 此前结论 | 现判定 |

| H1「翻译路径缺 F3 注入」是根因 | ❌ 作废（TRANS-F3-201/B 修的是真缺陷，但与本现象无关） |
| H2「CONDENSE 压制列表」 | ❌ 作废（单次样本；本轮未复测，但已非必要） |
| H4「提示词过长稀释」 | ❌ **作废** —— B 组在**同样 13,789 chars 的 F3 块**下达 90%，长度不是瓶颈 |

⇒ 🔴 **PROMPT-OPT-204（f3_lists 精简）不必做**。其立单理由（「精简是修复列表的正解」）已被证伪。
