## 2026-04-29 17:21 / coder-1 completed TRANS-KV-DEBUG-001

- Scope: diagnose why MarianMT `decoder_with_past` KV-cache never activated at runtime and repair the cached decode path in `src/translation/mod.rs`.
- Added targeted KV-cache diagnostics, then reproduced the issue with a local `translation_kv_probe` binary. The probe showed two concrete blockers:
  - `decoder_with_past` exposes `24` past inputs but only `12` present outputs, so the old metadata parser incorrectly required a 1:1 mapping and fell back before decode started.
  - Even after fixing that split, self-attn empty past `[1,8,0,64]` cannot be materialized through ORT `TensorRef`, so the old empty-past warm-up path still fell back.
- Reworked KV metadata parsing to:
  - parse `decoder_with_past` inputs independently from the full decoder input contract
  - classify `.decoder.` cache tensors as self-attn incremental cache
  - classify `.encoder.` cache tensors as cross-attn static cache
  - map warm-start outputs by `present.N.X.Y -> past_key_values.N.X.Y`
- Removed `build_empty_kv_cache`. Warm-start now uses `decoder([pad])` to extract all `24` full-decoder `present.*` tensors as `initial_kv`, clones that state across beams, and starts incremental decode with `decoder_with_past([first_token], initial_kv)`.
- Incremental update semantics are now correct for this model family:
  - self-attn cache entries update from `decoder_with_past` present outputs
  - cross-attn cache entries are carried forward unchanged
- Verification passed:
  - `cargo fmt --all`
  - `cargo check --manifest-path Cargo.toml`
  - `cargo test --manifest-path Cargo.toml`
  - local probe: same sample translation output, runtime improved from about `40.8s` / `44.6s` fallback runs to `9.9s` with no cached-path fallback warning
- Note: the sample's multi-sentence truncation behavior remained the same after cached-path repair, which points to model behavior rather than the KV-cache bug.
