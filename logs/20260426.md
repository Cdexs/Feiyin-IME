## 2026-04-26 / coder-1 完成 AUDIO-PREWARM-001
- 范围：
  - `src/audio/mod.rs`
  - `src/main.rs`
  - `tasks/todo.md`
- 独立评估：
  - 实际代码确认旧路径在每次 `AudioCapture::record()` 内重新选择设备、创建 `cpal::Stream`、`play()`，录音结束后 drop stream。
  - 主控根因成立：热键后建流成本会吞掉用户刚开口的前几个字。
  - 实施方案采用持久预热流，而不是改 hotkey/controller 合同；这样影响面最小。
- 关键改动：
  - `AudioCapture` 增加内部 `WarmInputStream`，持有 `cpal::Stream`、接收通道、设备标识和 stream error 标记。
  - 新增 `AudioCapture::prewarm()`，worker 启动时用当前配置尝试预热输入流。
  - `record()` 改为 `&mut self`，按设备复用已启动的热流；录音开始前 flush 预热期间的旧 chunk。
  - 音频回调由阻塞 `send` 改为 `try_send`，避免 idle 阶段通道满导致回调线程阻塞。
  - 设备名变化、默认设备实际名称变化或 stream error 后会重建流。
  - 补充 `src/audio/mod.rs` 单元测试：设备名归一化、热流匹配、stereo downmix。
- 验证：
  - `cargo fmt --all`
  - `cargo check --manifest-path Cargo.toml`
  - `cargo test --manifest-path Cargo.toml`（39 + 3 + 12 + 10 + 9 tests PASS）
- 备注：
  - 未执行 release 构建或真实麦克风 E2E，后续应交由 tester-1 验证热键录音首字不丢。
