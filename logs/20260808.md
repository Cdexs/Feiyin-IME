## 2026-08-08 — LLM-CONN-POOL-028 连接池僵尸连接修复

> 触发：Gavin 端测发现 LLM 优化间歇性 0ms 失败（请求未上网络即挂）。见 `docs/MACOS-HANDOFF.md` §2.9.5 跨端记录。

- **根因**：`reqwest::Client::builder()` 只设 `connect_timeout`，吃全局默认 `pool_idle_timeout=90s`；DeepSeek 服务端 keep-alive 约 60s 关连接 → 60-90s 窗口内池中残留「服务端已关、客户端以为活着」的死连接，复用即失败（失败点 62.5/67.9/72.3/72.8s，<60s 与 >98s 成功，与窗口假说吻合）。
- **改动 `src/llm/mod.rs`**：
  1. 新增 `POOL_IDLE_TIMEOUT=30s`（必须 < 服务端 keep-alive 余量）+ builder `.pool_idle_timeout(POOL_IDLE_TIMEOUT)`
  2. 重试判据 `e.is_connect() || e.is_timeout()` → `+ e.is_request()`（reqwest `Kind::Request` 桶，覆盖连接复用失败；body/decode/builder/status 各自独立桶不会误吞，已核 reqwest-0.12.28 error.rs）
  3. 新增 `fmt_error_chain`（逐层 `Error::source()` 展开），三处日志改用完整链路，解决 Display 吞底层错误的排障盲区
- **镜像 `src-tauri/src/llm.rs`**：同一 `pool_idle_timeout(30s)` + `is_retryable_error` 加 `is_request()`。
- **验证**：cargo fmt clean；cargo check 0 errors（dev 13.5s，pre-existing warnings）；`cargo check --manifest-path src-tauri/Cargo.toml` 0 errors（33.56s）；cargo test `llm::` 131/0；src-tauri 测试 53/0。
- **边界**：未改 CONNECT_TIMEOUT / ATTEMPT_TIMEOUTS / MAX_ATTEMPTS 现有值；未碰 itn.rs / prompt；未出包。
