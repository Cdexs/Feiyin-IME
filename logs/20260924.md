## 2026-09-24 — coder-1 实现 TRANS-CT2-DNNL-THREADS-397（阶段一）

**改动 1 · `Cargo.toml`（Windows 目标依赖）**：新增
`ctranslate2-sys = { version = "0.1.5", features = ["dnnl", "openmp-runtime-comp"] }`。
Cargo 做特性合并 ⇒ Windows 得到 `crt-dynamic/shared/ruy/dnnl/openmp-runtime-comp` 五项，
macOS 仍只拿通用三项（行为不变）。oneDNN 走 `ctranslate2-src-build-support` 自编 3.1.1 静态库。

**改动 2 · `patches/ctranslate2-sys/build.rs`（补丁，两处）**：

1. **DNNL 命中**：`link()` 编完 oneDNN 后（安装到本 build script 的 `OUT_DIR`），把 `OUT_DIR`
   前插进 `CMAKE_PREFIX_PATH` 再调 `build_native()`。CT2 的 `CMakeLists.txt:384-408` 只去
   `${INTEL_ROOT}/oneapi/dnnl/latest/cpu_gomp` 找 dnnl，而 `build_dnnl()` 装到 `OUT_DIR`，
   二者不通 ⇒ 不加必 `FATAL_ERROR: DNNL include directory not found`。改动**仅 dnnl 特性开启时生效**。
2. **DLL 影子**：shared 构建除拷到 `<target>/` 外，再拷一份到 `<target>/deps/`。
   根因见 `troubleshooting.md [CT2-DLL-SHADOW-397]`：`cargo test` exe 在 deps/，Windows 先加载
   exe 同目录 DLL，deps 旧副本会盖住新库（曾使 DNNL 提速零效果）。

**改动 3 · `src/translation/mod.rs`**：
- 新增 `nllb_num_threads()` = `available_parallelism().min(NLLB_THREADS_CAP)`，取不到回落 4；
  `NLLB_THREADS_CAP = 8`，与识别侧 `default_acc_num_threads()`（`src/transcription/mod.rs:133`）同口径。
- `NllbModel::new` 的 `TranslatorConfig` 传 `num_threads_per_replica: nllb_num_threads()`（原来 `=0`⇒4）；
  加载日志改为 `NLLB CT2 model initialized at <path> (threads=N)`。
- 新增 `#[ignore]` 基准 `bench397_real_model` + `#[cfg(test)]` 的 `BENCH397_THREADS` 覆盖（生产不读 env），
  复刻 `translate` 逐句流程分别计「首批 / 重译」耗时并校验复刻输出 == 生产输出。

**实测（debug bench，oneDNN 生效）**：基线（旧 DLL 4 线程）S1 6.1s / S2 13.9s / S3 17.6s / S4 30.5s；
新 DLL 8 线程 S1 0.39s / S2 1.16s / S3 1.31s / S4 2.75s ⇒ 提速 15.8× / 12.0× / 13.5× / 11.1×（远超 3× 目标）。
`CT2_VERBOSE=1`：`GEMM_S8 backend: DNNL (u8s8 preferred: true)` / `compute type: int8_float32` / `Selected ISA: AVX2`。

**影响范围**：只动 Windows 翻译运行时（CT2 库编译选项 + 线程数）。识别管线、在线/LLM 路径、翻译时机、
beam/分句/重译逻辑均未动；macOS 目标依赖不变。CT2 DLL 体积 8.2MB → 27.4MB（DNNL 静态）。

- Gavin：「本地的 performance 模型管线…也用的这个新翻译模型吧，也一并检查下调用是否 ok，不用再做测试，检查换模型后代码影响」⇒ 主控核 `src/main.rs`：Start 分三支——在线流式（:8089→`run_pipeline_core` :8264）、本地实时（:8334→:9160）、其余含 performance/accuracy 批量（:9244）；三处都进 `run_pipeline_core`→`run_llm_stage`（:12851）→`ensure_translation_direction`→`try_nllb_translate`，共用一份进程级 NLLB（`shared_model` 缓存）。397 只改库编译方式 + `NllbModel::new` 线程数，对三条管线一致生效；ctranslate2 全仓仅 `translation/mod.rs` 使用；翻译在识别结束后才跑，8 线程不与识别抢核。结论：无需另改。
