#### 分析

- **CTC**：tokens.txt 含标点 token 数=0（grep 确认）；`use_itn` 只管数字规整（"九点"→"9点"），无标点开关。**无法输出标点**，必须保留 punct-ct-transformer

- **结论**：

| 模型 | 自带标点 | 可开关 | 质量 vs punct-ct | 替代可行性 |
|------|---------|--------|-----------------|-----------|
| CTC | ❌ 无 | N/A | N/A | ❌ 不可替代 |
| native | ✅ 有 | ⚠️ prompt 理论可但不稳 | 标点质量好（语义停顿） | ⚠️ 仅 accuracy 可省，需联动 punctuation.enabled |

## [coder-1] ASR-PUNCT-OPT-001 · accuracy 模式启用模型自带标点 ✅

### 改动

#### 1. 来源标记（src/transcription/mod.rs）

- 新增 `transcribe_with_punct_info() -> Result<(String, bool)>`：返回 `(text, native_punctuated)`
- `transcribe()` 公开签名不变，内部委托 `transcribe_with_punct_info()` 丢弃 bool
- 标记规则：
  - performance → 恒 false
  - accuracy native 成功 → true
  - accuracy 兜底触发（fallback CTC）→ false
  - VAD 分段：所有段均 native 成功才 true；任一段兜底 → false
- 内部 `transcribe_offline`/`transcribe_segment`/`transcribe_2pass` 均拆出 `_detailed` 版本返回 `(String, bool)`

#### 2. 标点决策（src/main.rs run_pipeline）

- `transcribe()` 调用改为 `transcribe_with_punct_info()`
- 标点条件追加 `&& !native_punctuated`：native 自带标点时跳过标点引擎（省一次推理）
- 新增 strip 分支：`!punctuation.enabled && native_punctuated` → `strip_punctuation()` 剥离标点（修复"关了开关 native 照样出标点"缺口）

#### 3. strip_punctuation 函数（src/transcription/mod.rs）

- 剥离中英文标点（，。！？；：、""''…—,.!?;:"'()[]）
- 保守不剥离英文句号 `.`（保护小数点 3.14 / 缩写 Mr. / URL）
- 连续空格压缩 + trim

### 决策真值表

| 场景 | punctuation.enabled | native_punctuated | llm_handled | translate | 行为 |
|------|---------------------|-------------------|-------------|-----------|------|
| performance 任意 | true | false(恒) | false | false | 走标点引擎（与今天一致） |
| performance 任意 | false | false(恒) | false | false | 不走标点引擎（与今天一致） |
| accuracy native 成功 | true | true | false | false | **跳过标点引擎**（省推理，核心收益） |
| accuracy native 成功 | false | true | false | false | **strip_punctuation 剥标点**（修复缺口） |
| accuracy 兜底触发 | true | false | false | false | 走标点引擎（CTC 无标点） |
| accuracy 兜底触发 | false | false | false | false | 不走（CTC 本无标点） |
| 任意 LLM handled | * | * | true | * | 现有逻辑不动 |
| 任意翻译 | * | * | * | true | 现有逻辑不动 |

### ct-transformer 对已含标点文本行为结论

- **设计规避**：native_punctuated=false 时才走标点引擎，即只有 CTC/兜底文本（无标点）走 ct-transformer
- **唯一例外**：VAD 分段混合来源（保守策略整体 false）→ 拼接文本可能部分含 native 标点 → 走 ct-transformer
- **ct-transformer 行为**：CT2 标点模型标准行为是保留已有标点并补充缺失，不删除已有标点。对已含标点文本无副作用（不会重复加标点或删除）。保守策略安全。

### 三条红线自查

1. **performance 零改动**：native_punctuated 恒 false，标点条件 `&& !false` 等价不变 ✅
2. **LLM 协调**：llm_handled=true 时短路，标点段整体不走；native 文本进 LLM 无冲突（LLM 自己加标点时会覆盖原标点）✅
3. **兜底来源判定**：标记基于"文本真正出处"而非"配置选了 accuracy"——兜底/混合均 false → 照常走标点引擎 ✅
