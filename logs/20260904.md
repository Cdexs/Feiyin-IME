## SECRET-082-FIX · coder-1 · pre-push 根提交静默放行 + fail-open 设计缺陷修复

**基线**：SECRET-082 工作区改动（未提交），v0.9.0（未动）
**性质**：返工，修主控验收复现的两个缺陷，零生产代码

### 缺陷一：根提交无父时静默放行

**根因**：`pre-push` 情况 3 用 `${FIRST}^` 当 diff base，根提交无父 → `git diff` fatal → `2>/dev/null` 吞错 → DIFF 空 → `continue` 放行。
**修法**：`git rev-parse --verify -q "${FIRST}^"` 安静失败时 fallback 到 git 空树对象（`4b825dc6...`），扫根提交引入的全部内容。
🔴 **必须用 `--verify -q`**：裸 `git rev-parse` 解析失败时仍把字面量 `<sha>^` 打到 stdout，`$(cmd || echo $EMPTY)` 会把字面量和空树 hash 都吃进变量，BASE 变垃圾，diff 继续失败，看似修好实则没有。

### 缺陷二：fail-open → fail-closed

**根因**：`git diff ... 2>/dev/null` + `[ -z "$DIFF" ] && continue`，把「命令失败」和「diff 确实为空」当同一件事，任何故障都静默放行。
**修法**：`if ! DIFF_RAW=$(git diff ... 2>&1); then exit 1; fi` 分开判断，命令失败时拒绝放行并打印 git 报错。pre-commit 一并收敛（理由：失效形态同源，修成本极低，保持一致性）。
