## 2026-09-17 — V091-ITN-FIX-YIKE-216 指示代词 +「一」虚指护栏（Design B）

**改了什么**：`src/itn.rs` 新增纯函数 `is_demonstrative_yi`（三道判据）+ 在主循环
`check_protection`（`:1870`）之后、甲型（`:1880`）之前插入前置闸门；新增 6 组 `cfg(test)`
用例（a/b/c 组 + 越界红线 + 洞证据 + 刻意边界）。生产区 +37 行，测试区 +132 行，`itn-rules.toml` 零改动。

**为什么**：口述「那一刻」→「那1刻」。根因 = `decide_conversion` 的
`if r.is_date_suffix(after_str) { return true }`（`:2275`）不区分「数量词一」与
「指示代词构词成分一」—— 「刻」在 `itn-rules.toml:119` 的 `date_time.triggers.suffix` 里，
于是「一刻」被当「数字 + 时间单位」。同族远不止「刻」：那一年/每一年/这一点/这一秒/那一分/那一号
全部同病；`这一点我同意` 现在会变 `这1点我同意`（高频真实误转）。

**三道判据**：① 当前字是「一」；② 前一字 ∈ {这,那,每,哪,某}，或「那么/这么」形式
（前一字 `么` 且前两字 ∈ {这,那}，裸 `么` 不算）；③ **后一字必须命中时间后缀表**
（`r.is_date_suffix`，即 {年,月,日,号,点,分,秒,刻}）。

**🔴 闸门位置与第三判据是本单两次纠错的结果**（两次都由主控在派发/复核时拦下）：
1. 位置必须在**甲型之前** —— `那一年半` 会被甲型半模式抢先吃成 `那1.5年`，
   只改 `decide_conversion` 管不到甲/乙/丙三条路径；
2. 判据不能写成「后字非数字」（排除法）—— 那会让 `这一块八`（真数量，现状 `这1.8元`）的
   「一」被当成孤立字拦下，乙型隐式小数与丙型货币链整条被跳过，输出退化成 `这一块8`；
   同族还有 `这一块两毛`（1.2元）、`这一块五`（1.5元）。改成白名单（后字必须是**时间后缀字**）后，
   天然蕴含「一 后不接数字/进位字」：`那一百年`→`那100年`、`这一十年`→`这10年`、
   `那一千米`→`那1000米`、`这一万`→`这1万` 全部照常转。
   这正是 `[ITN-LOCAL-RULE-OVERREACH-001]`（局部规则在更长上下文里越界）的同一形状。

**红线遵守**：**未往保护表加任何词条**（DEC-038）—— 走文法护栏。
`itn-rules.toml:444` 的 `一刻钟` 保护条目**不得删**：删掉它 `decide_conversion` 会因
`"刻钟".starts_with("刻")` 命中时间后缀 → 输出 `1刻钟`。

**已知边界（刻意选择，非「暂不支持」）**：`这一点五`（1.5）/ `这一点半`（1:30）保持汉字。
理由三条：① `这一点` 压倒性是「这个观点」（`这一点我同意`），为罕见写法放行会打坏高频正确用法；
② 真要讲 1:30 的人通常不带「这」；③ `itn.rs:2977-3013` 历史注释证明「一点半/一点点」一带是雷区，
为罕见输入加分支的回归风险大于收益。**边界外护栏已钉**：`那两年`→`那2年`（两是真计数）、
`第一年`→`第1年`（ordinal 分支）、`怎么一年`→`怎么1年`（裸么不算指示代词）、`那两天` 现状不变。

**影响范围**：`src/itn.rs` 单文件；`itn-rules.toml` / `main.rs` / `config/mod.rs` / `ui/` 零触碰。
验证：`rustfmt --check src/itn.rs` 零 diff（**未跑全量 `cargo fmt`**，避免 `[FMT-COLLATERAL-001]`
连带格式化 coder-1 在途的 `main.rs` 等文件）；`cargo check` 与 `cargo check --all-targets` 均
0 error、warnings 111/102 与基线持平。🔴 测试断言系阶段一静态 trace 推得（禁 `cargo test`），
待阶段四 tester-1 实跑复核。

## 2026-09-17 — V091-ITN-YIKE-HANT-220 繁中异形字补丁 + 刻族刻意选择注释

**由来**：TEST-SYNC-216（阶段三）我的独立发现 ② —— `is_demonstrative_yi` 条件② 集合只含简体字面量，

**根因形状**：那 / 每 / 哪 / 某 **繁简同形** ⇒ 繁中用户处于「一半修好一半没修」的不一致半修状态

**改动（`src/itn.rs` 单文件，条件② 两集合 + 注释）**：

```rust
    // ② 指示代词（含「那么 / 这么」形式；裸「么」不算）
    // V091-ITN-YIKE-HANT-220：`這` / `麼` 为繁中异形字，一并覆盖。那/每/哪/某 繁简同形，不重复。
    let prev_is_demonstrative =
        i > 0 && matches!(chars[i - 1], '这' | '這' | '那' | '每' | '哪' | '某');
    let prev_is_me_form = i > 1
        && (chars[i - 1] == '么' || chars[i - 1] == '麼')
        && matches!(chars[i - 2], '这' | '這' | '那');
```

## 2026-09-17 — README 版本徽标改动态，消除「每次发版要手改」的复发点

**Gavin 端测发现**：v0.9.1 已发布，README 顶部 version 徽标仍显示 `v0.9.0`。

**根因**：徽标是 **shields.io 静态徽标**，版本号直接写死在图片 URL 里：
`https://img.shields.io/badge/version-v0.9.0-green`
它与 GitHub Release **没有任何关联**，只能每次发版手工改。
`VER-BUMP-217` 的任务书只列了 `Cargo.toml` / `src-tauri/Cargo.toml` / `tauri.conf.json` 三处，
**漏了 README 两份** —— 这是主控任务书的范围缺口，不是 Worker 执行问题。

**修法（不是改成 0.9.1，而是拆掉手改这件事本身）**：
换成 shields.io 的动态 release 徽标，直接读 GitHub 最新 Release：
`https://img.shields.io/github/v/release/Cdexs/Feiyin-IME?color=green&label=version`
以后发任何版本自动跟随，**永不需要再改**。

**顺带修掉同类的第二处**：README 底部「最新版本说明见 [v0.9.0 Release](.../tag/v0.9.0)」
也是写死的，改为 `/releases/latest`（中英两份）。

**核验**：改完两份 README grep `v0.9.0` 命中数均为 **0**，写死版本号已清零。

🔴 **教训（与 `[TOML-ALL-NUL-001]`、死规则同一形态）**：
修「这一处过期了」的正确做法是问**「它为什么会过期」**。
把 0.9.0 改成 0.9.1 只能让它在下个版本再次过期一次；
换成动态徽标才是把复发点本身拆掉。
