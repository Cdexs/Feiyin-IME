## 2026-10-17 — ASR-SERVER-491 B 方案 PoC：每终端一路推理

- **方案**：每接入一个远程终端，单开一路推理通道——共用 1.7B 模型权重和音频编码器，只多一份自己的上下文；本机有窗在解时，远程每生成一步就停下让本机。调度规则（Gavin 10-17 补充「每个终端一路推理」「平时一般只有一个终端在用，但功能上要支持多终端同时跑；配置好、有独显的机器并行能力更强」）：**本机永远优先（远程每步让行），远程之间不互相排队、各走各的通道**。弱显卡上远程之间自然变慢但不碍本机，强独显上远程自然并行吃满算力，无需新增配置项。
- **改动文件（只新增，本机路径逐位不变；未动版本号、未 commit）**：
  - `native/llama_asr/shim.cpp`：新增 `las_create_slot`（基于已加载引擎开一路推理，共用权重/编码器）；`las_free` 对通道只释放其上下文；音频编码器加一把共用锁（没有远程时没人争抢，本机路径行为不变）。
  - `src/transcription/llama_asr.rs`：新增测试用 `LlamaSlot`、`align_unlocked`；解码主体抽成 `decode_on`（引擎本体与通道共用，逐位不变）。
  - `src/transcription/poc_asr_server_491.rs`：新增 M4 / M5 场景与 `poc491_slot_same`。
  - 文档：`docs/ASR-SERVER-DESIGN.md` 新增 §15.7，并在 §4「本机优先调度」、§15.5 表后补指向；`collab/todo.md` ASR-SERVER-491 行加 491-B1/B2/B3。
- **实测**（AMD 780M；证据 `collab/evidence/491/poc491-concurrency-b.md`、`poc491-slot-same.md`）：
  - 结果一致性：17/17 窗，通道与引擎本体解出文字逐字相同。
  - 每路通道显存约 73MB（KV 缓存 59.5MB + 计算缓冲 11.3MB + 主机侧 2.3MB，上下文 1024，窗口更长时按需翻倍）；没有远程接入就不开通道 = 零额外占用。
  - 本机派发→定稿延迟（中位 / 最大）：M0 本机单独 1.94s / 2.44s；M3 旧闸门（整窗排队）2.05s / 3.62s；**M4 B 方案（各开通道 + 每步让行）1.88s / 2.61s**；M5 各开通道不让行、完全并行 2.48s / 4.56s。远程中位 2.3~3.1s，与其他方式相当。
- **结论**：B 方案本机中位不变、最坏只多 0.17s，是四种里对本机影响最小的；M5 证明 780M 上不让行会拖慢本机，所以每步让行必须保留。每路 73MB 也远低于此前按 `shim.cpp` 注释估的 0.2~0.3GB。
