## 2026-08-09 19:4x — TEST-EXEC-030 A0 起点自证异议裁决：纯行尾噪声，放行（无代码改动）

**tester-1 上报**：`git status -- src/` 有 14 文件 M，但 `git diff -w` / `--ignore-space-at-eol` 均空，
判定为 CRLF/LF 行尾差异（`scene/mod.rs` = `i/lf,w/crlf`），建议不处理行尾继续执行。

**主控独立取证（未采信 Worker 结论）**：

| 证据 | 结果 |
| --- | --- |
| `git status --short -- src/` | **完全为空**（不复现 14 M） |
| `git diff --stat -- src/`（**无任何 flag**） | **完全为空** → 零差异，比 `-w` 更硬 |
| `core.autocrlf` | `true`；**无 `.gitattributes`** |
| `git ls-files --eol src/` | `i/lf w/crlf` **恰为 14 个**，与 tester-1 报的 14 完全吻合 |
| `i/crlf w/crlf` | 0 个 |
| 本批五文件 | `itn.rs` / `llm/mod.rs` / `main.rs` / `punctuation/mod.rs` / `transcription/mod.rs` **均为 `i/lf w/lf`，不在 14 之列** |

**结论**：属 `[CRLF-CROSSPLAT-001]`（macOS 侧合并 `7e76465` 带入的行尾差异）。tester-1 看到的 14 M
是 git 索引 stat 缓存陈旧的**瞬时态**，`git status` 本身会刷新该缓存，故主控复查时不复现。
**裁决：放行 A1–A7，明令不得处理行尾。**

**顺带纠正 tester-1 一个方法论问题（值得记）**：不可把 `git diff -w` 为空当作放行判据 ——
`-w` 会连**真实的纯空白改动**一起吞掉；而本批 `llm/mod.rs` 大量内容是提示词字符串常量，
**字面量内部的空格是语义的一部分**（改一个空格就改了送给 LLM 的提示词），`-w` 在此场景判别力不足。
已明令今后一律以**无 flag 的 `git diff`** 为准。

**红线重申给 tester-1**：禁止对这 14 个文件执行任何行尾归一化 / `git add` / `git checkout` / `git stash`
—— 依据 `[CRLF-CROSSPLAT-001]`，碰它们会制造 4800 行幽灵 diff。
