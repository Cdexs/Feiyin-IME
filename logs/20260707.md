## [coder-1] RESEARCH-ASR-ACCURACY-001 完成 ✅

- 范围：纯研究，生产代码零改动
- 方法：扩展 PoC bin 跑 16 组 A/B + 6 种前导静音曲线 × 3 模型配置，复用 002B 40 wav 语料 + 模拟生产音频（600ms pre-roll / post-trim 50ms head）
- 上游调研：WebFetch sherpa-onnx PR #3122 确认 hotwords 为 prompt-based（注入 user_prompt，吃 max_total_len=512 context 预算）+ ITN 默认不生效 + 无 fp16 替代模型
- 根因（按贡献度）：
  - R1 主因：生产音频前处理为 CTC 调优，对 native decoder 伤害大。silence curve 证实 native 无 hw 50ms 静音头掉 10pp（67.5→57.5），CTC 仅掉 2.5pp。post-trim 模拟 CTC 70% vs native+hw 65%
  - R2 次因：hotwords 全量灌入副作用。精选 20→80%，全量 11 条→60%（比无 hw 还差），220 条→0%（撑爆 context）
  - R3 次因：native 固有 hallucination（qidian_v1 产 80 字中英混杂串），生产兜底正确触发但用户感知"accuracy 无效"
- 假设验证：H1/H2/H3/H4/H6/H7 成立（H3 主因），H5 推翻（VAD 与短音频无关）
- 优化方案：A（hotwords 精选，低风险，+2~5pp）+ B（accuracy 前处理适配 silence head 50→0ms，中风险，+5~10pp）合并预期 accuracy 生产 first% ~57→~70% 与 CTC 持平
- 产出：collab/research/asr-accuracy-quality-001.md + 实验脚本 4 个 + accuracy_study/ 数据目录
