## 2026-09-21 — 主控根因分析：本地流式「中间句必丢尾字」（FIX-LOCALRT-TAILCHAR-291）

**输入**：Gavin 端测 BUILD-290 报两条 —— ① 首字仍不准 ② 长连续输入中**中间句**丢尾字。
**证据保全**：`target/release/debug.log`（406 行，02:00–02:20）即时 `cp` 进
`collab/evidence/20260921-gavin-e2e/debug-1018.log`，sha256 `b42c82341aff22b03717650ffbb7adaf4cae1dfb7a519288f3c13387adda3163`
（`[EVIDENCE-LOG-VOLATILE-001]`：该路径下次运行即被覆写）。

### 根因（结构性，非概率性）

`src/transcription/local_stream.rs::transcribe_streaming_local` 全函数只有**一处**
`stream.input_finished()`，位于 loop 之后（`:536`），只服务「录音结束时的最后一句」。
中间句的终止走 `if endpoint { recognizer.reset(&stream); … }`（`:415` 附近），
**reset 之前从未 flush** ⇒ sherpa 解码器里未吐出的最后一个 token 被 reset 丢弃。

⇒ **每一个被 endpoint 切掉的句子，结构上必然少最后一个字**；最后一句因有 flush 而完整。
与 Gavin 描述的「**中间的**句子」逐字吻合。

### 284/289 影子机制为何没兜住

1. `shadow_done_for_pause` 在该轮静默的**第一个 400ms 刻**上锁，此后 main 仍在增长
   ⇒ endpoint 时恒 `shadow_len < main_len`，289 的 `use_shadow` 条件恒假。
   日志 5 次 `[LocalRT-DBG-289] endpoint confirm` **全部 `used=main`**。
2. 句长超 `SHADOW_MAX_AUDIO_SECS=12s` 时影子整个跳过（02:00:56 / 02:01:00 两条
   `shadow skipped: 18.5s > cap 12.0s`），endpoint 时影子停在 23 字而 main 已 45 字。

**反向价值**：`shadow finalize #6`（02:00:07.450）`text_len=15` 而同刻 main 仅 14
⇒ `input_finished()` 确能多吐一个字，291 方案（endpoint 先 flush 再确认）据此成立，
非「能解释症状即宣布已修」（`[PLAUSIBLE-FIX-NOT-ACTUAL-CAUSE-001]`）。
