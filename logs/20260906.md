## REPRO-114 · 热键第二下按不停根因定位（tester-1，2026-09-06，只查不修）

**Gavin 手测复现（P0）：按下热键有时出现录音窗口、有时不出现；按第 2 下经常不停止、录音也不退出。**

### 根因（决定性定位，probe3 逐句镜像生产代码复现）

**`src/platform/windows/hotkey.rs:221`** —— WM_KEYUP 分支 `PTT_ACTIVE.store(false)` **无条件执行**，
Toggle 模式下把第一下按下置 true 的标志在松键时重置 → 第二下按下判定 `!PTT_ACTIVE==true` → **又发 Start 而非 Stop**。

**RegisterHotKey 路径（F9 等）另有缺陷**：`hotkey.rs:536-547` Toggle 分支无 toggle 状态，每次触发都发 Start。

### 实验证据链

| 实验 | 结果 |
| --- | --- |
| probe1（镜像生产回调 spawn+send，SendInput 自驱动） | 钩子收到 20 次事件，回调 **60-83us**（默认超时 1000ms 的 1/10000） |
| probe2（+loader-lock 压力线程 LoadLibrary d2d1/dwrite 等） | 钩子仍 60-83us 正常，**H1 loader-lock 假设证伪** |
| probe3（逐句镜像生产 PTT_ACTIVE 逻辑） | **决定性复现**：两次 DOWN 都 START，第一次 UP 无条件重置 PTT_ACTIVE |
| 真实 app 双按（exp_fast_slow） | gap=1000ms 与 20ms 都复现第二下恒为 Start；最终 overlay 卡 recording ~20s |
| 真实 app 单按（×5） | 第一下 5/5 都进 recording（第一下可靠） |
| RegisterHotKey 路径（F9 配置） | 两次都 `Controller received hotkey start`，无 Stop |

### 判定

- **H1（loader lock → 超时摘钩）：不成立**（probe2 证伪）。
- 根因在 **PTT_ACTIVE 生命周期逻辑**（非阻塞，非环境）。
- 两条热键路径（hook / RegisterHotKey）都缺 toggle-stop 语义。

### 建议修法（交 coder）

1. `:221` 把 `PTT_ACTIVE.store(false)` 移入 `if should_stop_translate_poll_on_keyup(mode)` 块内（仅 PTT 松键重置）；
2. `:536` RegisterHotKey Toggle 分支加入 `PTT_ACTIVE` toggle 状态（第一下 Start、第二下 Stop）。

## HOTKEY-115-C · 陈旧 KEY_PHYSICALLY_DOWN 自愈（coder-1，2026-09-06）

- **新失效模式（主控指出，采纳）**：KEY_PHYSICALLY_DOWN 成唯一 DOWN 闸门后，一次未见的
  KEYUP（Win+L 锁屏安全桌面 / 上游吞 KEYUP / 钩子重装窗口）→ 标志永久 true → 热键失灵
  到重绑定，比 repeat 掷硬币更严重。
- **判据选型：时间戳，不用 GetAsyncKeyState（主控建议反向，已给理由）**：DOWN 到达时真
  repeat 与陈旧后的新按下键都处于按下态，GetAsyncKeyState 高 bit 判别力为零；LSB 转变位
  文档明示多进程下不可靠。时间戳可用但阈值 🔴 必须 > Windows 重复延迟上限 1000ms
  （250/500/750/1000 四档；只按 33ms 取阈值会在长延迟设置下让首个 repeat 误判陈旧、
  抑制退回翻转），取 2 倍 = 2000ms。
- **实现**：`LAST_TARGET_DOWN_TICKS`（AtomicU64，GetTickCount64 ms，时间戳随每次 DOWN
  无条件刷新）+ DOWN 分支 `!was_down || now.saturating_sub(last) > 2000` 进首次按下路径。
  长 hold 期间间隔被连续刷新恒 < 阈值 ⇒ 真 repeat 永不误判；吞 UP 后秒级重按 > 阈值 ⇒ 自愈。
  残余窗口（2s 内重按仍被吞一次）如实声明。陈旧自愈进状态机后动作由 TOGGLE_ACTIVE/
  PTT_ACTIVE 语义态决定，行为正确。
- **时间戳无需复位点**：仅在 was_down=true 时被参考，三处复位点均清 KEY_PHYSICALLY_DOWN
  ⇒ 复位后必走 !was_down 分支。
- **验证**：fmt --check 0 / check --all-targets 0 error（新增 SystemInformation 导入）/
  warning 持平（111/102）；未 commit；v0.9.0 未动；零凭证。
