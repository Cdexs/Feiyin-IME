# 2026-05-26 改动日志

## FIRSTCHAR-FIX-004 — D3 时间戳精确清空

**负责人**：coder-1（编码）

### 根因

FIRSTCHAR-FIX-003 的 full drain 虽然清空了所有陈旧 chunk，但也会误清热键触发后 1-20ms 内到达的首字 chunk。
D3 方案通过为每个 WASAPI chunk 打上 `std::time::Instant` 时间戳，只清空热键触发时刻之前的陈旧数据，
精确保留热键后的有效首字音频，从根源上消除竞争窗口。

### 代码变更

**文件**：`src/audio/mod.rs`

**类型变更**：
- 新增 `type AudioChunk = (Instant, Vec<f32>);` — 每个 chunk 携带 WASAPI 回调产生时间戳
- Channel 类型 `crossbeam_channel::bounded::<Vec<f32>>(256)` → `bounded::<AudioChunk>(256)`
- `WarmInputStream.rx` 类型 `Receiver<Vec<f32>>` → `Receiver<AudioChunk>`

**WASAPI 回调（3 处）**：
- F32/I16/U16 三个回调中 `try_send(chunk)` → `try_send((Instant::now(), chunk))`
- 错误回调 `try_send(vec![])` → `try_send((Instant::now(), vec![])`

**record() idle drain（L122-146）**：
- 旧（FIRSTCHAR-FIX-003）：`while let Ok(_) = warm.rx.try_recv()` 无限清空全部 chunk
- 新（FIRSTCHAR-FIX-004 D3）：`loop { match warm.rx.try_recv() { Ok((ts, chunk)) => if ts < record_start { discard } else { preserve } } }`
- 新增 `record_start = Instant::now()` 作为热键时刻锚点
- 新增 `post_hotkey_chunks: Vec<Vec<f32>>` 保存热键后的有效 chunk

**collect_recording()**：
- 签名新增 `post_hotkey_chunks: Vec<Vec<f32>>` 参数
- Prime（冷启动）路径：将 `post_hotkey_chunks` 作为种子注入 `prime_samples`
- Warm（热启动）路径：在 `pre_roll_chunks` 处理后通过 `push_chunk` 逐一喂入 `post_hotkey_chunks`
- 主录音循环 `rx.recv_timeout` 解包从 `Ok(chunk)` → `Ok((_ts, chunk))`

**测试更新**：
- `idle_channel_drain_terminates_on_empty_channel` → `timestamp_idle_drain_terminates_on_empty_channel`：验证空 channel 上精确清空迭代 0 次
- `idle_channel_drain_clears_all_pending_chunks` → `timestamp_drain_clears_pre_hotkey_preserves_post_hotkey_small`：验证 3 个 pre-hotkey chunk 被清空、0 个 post-hotkey chunk
- `full_idle_drain_clears_all_chunks` → `timestamp_drain_clears_pre_hotkey_preserves_post_hotkey_large`：验证 120 个 pre-hotkey 清空 + 2 个 post-hotkey 保留
- `full_idle_drain_stops_when_empty` → `timestamp_drain_stops_when_channel_empty`：验证 30 个 pre-hotkey 清空后停止

### Orchestrator 验收修正（2026-05-26）

**问题**：coder-1 用 `record_start = Instant::now()`（L126，在 ensure_stream + drain_pre_roll 之后捕获）作为 drain cutoff。冷启动/流重建场景 ensure_stream 耗时 100-500ms，期间新流捕获的首字 chunk 时间戳 < record_start，会被误判为陈旧清空——正是 troubleshooting C3 冷启动首字丢失场景。

**修正**：drain cutoff 改用函数开头的 `t_record`（L110，最接近热键触发时刻）。删除 L126 的 `record_start`，drain 判断改为 `if ts < t_record`，并更新注释说明理由。副作用仅 ~1-5ms pre_roll/post_hotkey 边界微量重叠（远小于一个音节，不影响 ASR）。

## FIRSTCHAR-FIX-003 — idle_clear full drain

**负责人**：coder-1（编码）/ tester-1（构建验证）

### 根因

crossbeam_channel::bounded(256) 满载时，idle_clear 仅清 pre_roll_chunk_count（≈60）个 chunk，
剩余 ~196 个陈旧背景 chunk（≈2s 旧噪音）混入录音。
短词（"派对"≈0.5s）：噪音占比 80%，SenseVoice 完全识别错误。
长句（>2s）：语音占主导，识别正确。

ring buffer（PREROLL-RINGBUF-001 引入）已抓取热键前 600ms 语音，
channel 完全清空安全：只移除陈旧背景，不丢有效语音。
