却要为每次加字段付维护成本。按 `feedback_security_rules_need_gates`：**假闸门比没闸门更糟**。

**残余风险处置**：新增 `[CONFIG-MIRROR-DRIFT-001]`（archive 全文 + 索引一行）。

**为什么要纠正一个已被采纳的结论的理由**：理由会被复用。若让「同义反复」这个不准的判据
留进 result.md，下次有人引用它去否掉一条真正必要的 schema 级护栏。

## RESEARCH-LOCAL-STREAM-233（第二轮）· 本地流式 ASR 候选模型普查 · 主控

- **触发**：Gavin 问「有哪些开源/可本地部署的 ASR 模型能真流式、首字延迟低、质量接近在线 fun-asr-realtime」。
- **产物**：`collab/research/local-streaming-asr-233-model-survey.md`（第一轮只查了 API 可行性与 2023 年老模型，本轮补 2025-2026 新模型 + 统一口径 CER）。
- **关键否定**：sherpa-onnx Discussion #3063 维护方明确答复 —— FunASR-nano **无真流式支持且无路线图**，只有切块伪流式（DEC-051 已否决）。配套证据：`OnlineModelConfig`（crate 1.12.38 `online_asr.rs:128-134`）五个槽位无 `funasr_nano`/`sense_voice`。
- **关键参照物**：FireRedASR2S 统一对比表给出 Fun-ASR（7.7B，我们在线那一家的大模型）离线 CER **4.16%**，首次让「本地 vs 在线」可量化。
- **候选与实测**：icefall RESULTS.md 四集平均 —— zipformer-large 流式 **5.62%**（实测）／ 离线 4.49%／ zipformer-XL 离线 **4.33%**（XL 流式官方未公布，按 large 的 25% 流式惩罚推算 ≈**5.4%**）。
- **结论**：「接近」做得到，「持平」做不到，差 1~1.5 个百分点绝对值。三个额外收益：首字延迟可能更低（无 RTT）、**transducer 拿得到 per-stream 热词**（`create_stream_with_hotwords` 仅对 transducer 生效，`POC-QWEN3ASR-002A` 已实测）、断句权回到本地（治 ASR-SEG-229 同类问题）。
- **门禁未解**：XL（700M 参数、int8 730MB）在 Ryzen 7840HS 纯 CPU 上的 RTF 完全未知，建议先出独立 PoC bin 量首字延迟 + RTF，不碰生产代码。
