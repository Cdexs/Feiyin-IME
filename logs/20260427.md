## RESEARCH-CONFIG-SYNC（coder-1，2026-04-27 23:02:00 +08:00）

- 范围：仅方案评估，未新增代码实现。
- 现状：settings UI 通过 `save_config` 写磁盘，main 进程持有 `Arc<RwLock<AppConfig>>` 内存副本，hotkey listener 读取该 Arc；磁盘写入与内存更新之间缺少显式同步协议。
- 方案 A：main/controller 定期或事件前从磁盘 reload 到 Arc。优点是改动小、适合止血；缺点是磁盘作为隐式总线，若放在 15ms timer 上会造成高频 I/O 和重复 TOML parse，且需要 mtime/debounce 与 atomic save 降低风险。
- Gavin 追加约束：方案必须跨平台（Windows + macOS），不能依赖 Windows 专有 API。
- 方案 B：跨平台推荐优先使用 Rust `notify` crate 监听 config 文件变化，main 收到事件后 debounce reload 到 Arc；该方案在 Windows 走 ReadDirectoryChangesW、macOS 走 FSEvents/kqueue，但由 crate 屏蔽平台差异。
- 进阶方案：settings 保存后显式通知 main，或由 main 作为配置单写入服务，先更新 Arc 再原子写磁盘。架构最干净，但跨平台 IPC/config service 工程量明显更大。
- 推荐：短中期采用 `notify` watcher + debounce + atomic save；长期再演进到跨平台 main-owned config service。
