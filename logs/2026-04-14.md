## 2026-04-14 — 切换主控架构并恢复设置/热键/退出链路

- 将主程序从 `eframe` 宿主模式切换为 Win32 controller：主线程负责 tray、hotkey、worker、overlay、shutdown 的统一消息分发。
- 将设置窗口拆为独立 `--settings-ui` 入口，不再依赖 root viewport 的显隐切换来唤起配置界面。
- 将录音波形、处理中提示、失焦预览切换为原生 Win32 overlay，避免继续依赖 `eframe viewport` 做短生命周期悬浮层。
- 将热键链路从低层键盘 hook 调整为 `RegisterHotKey`，并保留 `PTT` 模式下的释放检测逻辑。
- 退出路径改为 controller 统一 shutdown，不再把“关闭某个窗口”等同于“退出应用”。

影响范围：
- `src/main.rs`
- `src/hotkey/mod.rs`
- `collab/decisions.md`
- `collab/troubleshooting.md`
- `collab/progress.md`
- `collab/todo.md`

当前验证结果：
- 用户已验证：配置窗口第一次即可正常显示。
- 用户已验证：按热键后音频波形窗口能够显示。
- 用户已验证：选择退出程序后主程序能够正常退出。

结论：
- 本轮已完成从失败的 viewport 路线向 Win32 controller 方案的切换。
- 后续问题排查应继续沿 controller / settings / overlay / hotkey / worker 的职责边界推进，不再回到旧的 root viewport 方案。

## 2026-04-14 — 修复设置页优化模型探测误报失败

- `src/llm/mod.rs` 中的 `probe()` 已对齐 `optimize()` 的三次重试逻辑，仅对连接/超时类错误重试。
- probe 请求现在固定携带 `max_tokens: Some(5)` 和 `stream: Some(false)`，降低延迟并规避部分兼容性问题。
- probe 失败时会区分连接超时、认证失败、4xx 请求错误，并把友好错误文案直接展示到设置页。

影响范围：
- `src/llm/mod.rs`
- `src/main.rs`

## 2026-04-14 — 修复 overlay 尺寸、处理中胶囊形与透明度配置接线

- `src/main.rs` 中录音/处理态 overlay 改为 `480x52`，并按新尺寸重排取消按钮、分隔线和波形区。
- 处理中状态现在沿用胶囊窗口 region，并在 `draw_processing_overlay()` 内补回圆角背景和蓝色居中文字。
- 原生 overlay 已通过 `OverlayRequest.opacity`、`WS_EX_LAYERED` 与 `SetLayeredWindowAttributes` 接入设置页已有的透明度配置。

影响范围：
- `src/main.rs`
- `src/ui/settings.rs`（透明度滑条已存在，本次确认沿用）
