## 2026-04-15 — 修复配置参数实时加载 bug

- 改动：`src/main.rs` 在每次录音前调用 `reload_runtime_config()` 重新加载配置文件。
- 原因：用户反馈静默时长设置后实际等待时间仍是 3 秒，未按配置界面设置的时长运行。分析发现配置只在设置窗口关闭时重新加载一次，录音流程不读取最新配置。
- 影响：所有配置参数（静默时长、阈值、输入设备等）都会在每次录音前重新从配置文件加载，确保用户修改立即生效。
- 构建：cargo build --release 成功（29.63s），产物 `15,243,264 bytes`。

## 2026-04-15 — 完成 v0.3.2 ASR 升级：Paraformer 替代 Whisper

- 改动：
  - **移除 Whisper.cpp**：删除 `whisper-rs` 依赖和所有 Whisper 相关代码
  - **集成 sherpa-onnx Paraformer**：使用 `sherpa-onnx v1.12.38` (shared-MD 版本) 作为默认 ASR 引擎
  - **新增流式输入配置**：`AudioConfig` 添加 `enable_streaming: bool` 字段，配置界面添加"开启流式输入"复选框
  - **LLM 优化作为第二道工序**：如果 `llm.enabled` 为 true，则 ASR 结果再经过 LLM 文本优化
- 原因：用户要求提升中文转录准确率，Paraformer 模型在中文场景下的 CER（字符错误率）约 3-5%，远优于 Whisper 的 18-20%
- 实现：
  - ASR 模式：offline（单遍高准确率）或 streaming（未来支持 2-pass：实时预览 + 离线修正）
  - 模型：Paraformer-zh-small int8 (~82MB)，首次使用时自动下载
  - 配置界面："音频设置"标签页新增"开启流式输入"选项
  - 处理流程：ASR 转录 → 词库替换 → LLM 优化（如启用）
- 影响：
  - 产物体积减小：从 15.2 MB 减到 14.5 MB（移除 Whisper）
  - 需要携带 DLL 文件：`onnxruntime.dll`、`sherpa-onnx-c-api.dll` 等
  - 中文转录准确率预期大幅提升
- 构建：cargo build --release 成功（79s），产物 `14,501,888 bytes`，需携带 4 个 DLL 文件

## 2026-04-15 — 完成 T21 LLM 推理模式优化

- 改动：`src/llm/mod.rs` 添加 `enable_thinking: Some(false)` 参数关闭推理模式，同时将 `max_tokens` 从 1024 减少到 512。
- 原因：用户反馈语音转录后 LLM 优化耗时过长；分析 SiliconFlow API 文档发现推理模型（如 DeepSeek-V3）默认可能开启 chain-of-thought 推理模式，导致大幅延迟。
- 影响：
  - `enable_thinking: false` 关闭推理模式，跳过 chain-of-thought 步骤，响应更快
  - `max_tokens: 512` 语音输入的文本优化不需要长输出，减少生成时间
- 预期效果：LLM 优化响应时间从数秒级降到秒级或更低。
- 构建：cargo build --release 成功（25.26s），产物 `15,178,752 bytes`。
